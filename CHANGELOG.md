## [0.27.0] - 2026-09-05

### Added

- Task Board: Bot dropdown + BellDot toolbar filters for lead-agent work (lead:/lead-wait:/lead-dedup: tags), an in-place TaskCard expander showing domain/priority/complexity, and a bot glyph beside the project pill for lead-originated cards (FR-04.11).
- Inbox: a new 'lead_question' card kind surfaces a leadwright follow-up question with an inline answer field (PATCHes the task's PO feedback) and Dismiss.
- Org page now renders each lead's follow-up conversation (question/answer rounds, in order, with open rounds clearly marked) beneath their card, once leadwright's round data lands (FR-04.42).
- Task Board: claimed cards now show a chip naming who holds them and since when, and a toolbar toggle filters the board to claimed tasks only.
- Org page follow-up threads now render leadwright's real round-store data (GET /api/org/threads) instead of an empty stub.
- Desktop sidebar can now be collapsed to icons-only via a toggle button; the choice persists across reloads and defaults to expanded.
- Diagnostics page now shows the WebUI version and the current Shipwright plugin version.

### Changed

- The vendored Tier-3 PR-review gate now defaults to GLM 5.3 (z-ai/glm-5.3) instead of DeepSeek, after DeepSeek was found to repeatedly hallucinate a false block verdict on the canonical monorepo's PR #668. DeepSeek remains available as an operator override via SHIPWRIGHT_PR_REVIEW_MODEL.
- Org lead cards now label spend as '{N}-day USD consumed' (never 'budget'), name the un-counted subagent-spend gap, surface unpriced-call counts, and distinguish no-data / partial / complete measurement windows.

### Fixed

- Bootstrapper port probe now follows SHIPWRIGHT_NETWORK_PROFILE instead of hardcoding loopback, fixing attach/swap detection under `SHIPWRIGHT_NETWORK_PROFILE=tailscale` (#415)
- The claim holder can now (re)launch a claimed task by presenting the current claimToken within a 24h window, instead of being refused by the same 409 that blocks everyone else
- pr_review.py now logs a bounded, scrubbed decision excerpt (decision, exit code, summary) to CI stderr on every outcome, not just unknown decisions — a legitimate block/approve/comment no longer looks like a silent hang in CI logs (ports canonical shipwright PR #674)
- Mission Activity Feed no longer prints templated filler text ("The implementation was updated in compact steps.", "This test command completed.", etc.) for tool calls — cards show Claude's own narration or nothing; long text (headlines, explanations, test output, question answers) and long Bash commands can now be expanded to their full untruncated content instead of being permanently cropped; a successful review's own findings now reach the feed even without a durable review artifact; and the requirement/spec/decision backfill cards show the server's real summary instead of a generic placeholder
- Embedded terminal: a first task launch with a long prompt could freeze the whole server on macOS — the launch command is now written into the pty in sub-KB chunks instead of one oversized burst that could deadlock the shell's input queue.

### Security

- Launch's claim check now re-reads the claim fresh from disk under the store's write lock before refusing, closing a stale-cache window where a long-running webui process could miss a claim another process (e.g. the leadwright daemon) had already written, letting two runners launch the same task

## [0.26.0] - 2026-09-01

### Added

A one-time npmjs.com Trusted Publisher setup (org svenroth-ai / repo shipwright-webui / workflow publish-npm.yml) is needed before the first automated publish.

### Fixed

- Reconciled 4 open compliance audit findings (B7/H1/H2/H6): backfilled a missing commit event, added 6 untracked oversize files to the bloat baseline, tightened 15 stale ratchet ceilings to their real line counts, and pruned 3 baseline entries for deleted files

## [0.24.0] - 2026-08-08

### Added

- Launching a campaign or a step is now visible and recoverable from start to finish. A planned (draft) campaign shows up on the board with a status badge and a "Start campaign" button, so you no longer have to open Triage to begin it. Every launch first shows a plain confirmation — what will run, in which project, and the exact command — and an autonomous run also lists the remaining steps and warns it won't ask again; Cancel does nothing. Most importantly, a launch that fails is no longer silent: whether the command never ran, no transcript appeared, the folder can't be written to, or the campaign already finished, you get a clear message that stays put (never a toast that vanishes when you switch tabs) with the right way forward — a Retry only when retrying can actually help, otherwise the fix stated plainly. The same wording appears on the campaign card, the board task card, and the task page, so a failure reads the same everywhere.
- The Command Center now drives from the keyboard. Press Ctrl+K (Cmd+K on a Mac) anywhere to open a search palette that jumps to a project, opens a screen, starts a task from that project's real actions, or filters the board — it floats as frosted glass over the backdrop, and the most recent commands come first. Press "?" for a cheat-sheet that shows every shortcut with both the Windows and the Mac keys side by side (Windows is the default, so a Mac-only hint never shows on Windows). In the board, projects, triage and inbox lists, "j" and "k" move a visible selection and Enter opens it; on the board list "L" launches the highlighted task. A comfortable/compact density control (in each list's header and in the palette) tightens the rows and is remembered across reloads. On a task screen, "t" jumps focus into the terminal and maximises it. Crucially, while you are typing in the terminal or any text box, every one of these shortcuts stands down — the letters you type reach Claude unchanged, exactly as before. Screens you have already loaded now repaint instantly from cache instead of flashing a spinner.
- The design-approval step now lives inside the task's Mission view instead of a separate screen. When a run pauses for your sign-off, the Mission view shows the same three-card layout as everywhere else: the Record on the left (with "Design" marked as the step you're on), a gallery of the actual proposed screens in the middle — each a real, clickable preview, not a grey box — and one clear "Approve — start building" button next to "Request changes". Approve confirms in two clicks so you can't fire it by accident, and it runs the exact same Resume action as always (the Command Center never drives Claude itself). While you're deciding, the competing "Resume" button in the header steps aside so there's only one primary action, and the Tests/Serves badges stay honestly empty (a design gate happens before any tests exist). If no previews were produced, you get an honest "nothing to show yet" message rather than a fake gallery. "Request changes" writes your feedback exactly as before. The gate clears itself the moment the run moves on — no refresh needed.
- Weather-Deck design system: one signature photographic backdrop (`deck-golden.jpg`) behind every route via a frozen scene layer + frosted-glass panels, the warm-neutral token set exposed to Tailwind utilities, and the `.on-photo` token-flip with a solid-surface reset so bare chrome reads light on the photo while cards stay dark-on-white. Ships an AA contrast ladder machine-checked against WCAG 2.1 (every text token clears 4.5:1 body / 3:1 large against its worst-case ground, incl. two grounds derived from the real backdrop) — the four measured legibility failures are fixed or explicitly re-roled. Design foundation for the remaining Command Center repaint (FR-01.48; no data or behaviour change).
- Tracked event-log reader: a read-only `GET /api/external/projects/:projectId/events[?runId=]` endpoint over each project's `shipwright_events.jsonl`, projecting per-run facts (commit, tests, summary, spec-impact, affected FRs, phase transitions) for the Mission-Control / Ship's-Log surfaces. Durations degrade honestly to `n/a` when absent — never fabricated (FR-01.46).
- Plain-language glossary + teaching empty states on the Inbox, Task Board, and Projects surfaces, plus just-in-time tooltips on the create-dialog phase chips — one bank of the jargon (IREB / ADR / RTM / SBOM / FR / Spec / Canon / Gate, the pipeline phases, and the two mid-run prompt kinds), each with its one-line plain-language explanation shown right where it appears (FR-01.50).
- E2E harness gates: `E2E smoke (gate)` + `Visual regression (gate)` now run on every PR inside the pinned Playwright container. 114 Playwright specs existed before; none of them could block a merge.
- Visual-regression baselines for all 8 routes that exist today, plus a route manifest (`client/e2e/visual/routes.ts`) whose guard fails if a route is neither baselined nor explicitly pending with an owning sub-iterate.
- Terminal byte-path guard: pins the exact bytes the client sends to the pty (auto-execute / keystroke / paste, incl. bracketed-paste markers). The existing corpus only pinned the server→client direction.
- Intent Wizard — the guided three-door front entry (`/wizard`, `/wizard/adopt`, `/wizard/grade`) placed before the expert project wizard. **Build something new** walks four plain-language questions (with example chips + smart defaults) to a plan card, with a live "flight-plan" rail that translates each answer ("Because you said X → Y") and shows unanswered fields as dim spine nodes. **Adopt** picks a folder → a real working screen (lists the steps; nothing written/uploaded) → a two-column result (what's already here / what adopting writes) that ends in a Mission task. **Grade** takes a folder or a GitHub URL → a working screen (showing the shallow-clone step for a remote) → a Control-Grade card that renders the `shipwright-grade` `ReportModel` field-for-field: the ring, the four dimensions with per-dimension provenance and the honest-ceiling note above them, "why this grade", "what adopting would light up", and a "what left your machine" receipt — with a shape-guard that renders an honest "report shape not recognised" state rather than a half-empty card. The honest `n/a` is load-bearing: `status` drives the visual, and no code path can synthesize a score for an underivable dimension. The First-Contact readiness line is now a real GATE (`GET /api/readiness`): it re-expresses the bootstrapper preflight set server-side (Claude CLI ≥ min · the door-critical plugins installed · a coherent `cache/shipwright/shared/` · uv · a test-run Python ≥ 3.11 · git); when not ready the three doors are inert and the missing prerequisites, why they matter, and the one repair command are named. The board empty-state opens the wizard; a quiet "Already set up? Add the existing project" line routes to the classic registration. UI-only for now — scan/grade data is a provenance-tagged sample marked not-live (the real `/shipwright-adopt` · `/shipwright-grade` launches land next) and the expert project wizard stays reachable, unchanged (FR-01.51).
- Mission Control "Operation" card: the middle card that answers "what happened, and can it ship?" — a derived verdict banner, a one-sentence plain-language mission line, and a curated, read-only proof summary. The verdict is derived, never decorative: `ALL CLEAR` requires affirmative evidence (a fully green suite and passing review and security gates), `GATE HOLD` requires a real failing security gate, and with missing/partial run data the banner shows an honest neutral state ("No run data yet" / "In progress" / "Not fully verified") — never a false ALL CLEAR over an unknown run. Because the server does not yet emit review/security gates, a real green run honestly reads neutral today and will light ALL CLEAR once those gates are wired. The proof summary is a short (≤8), curated list of proof lines built from real per-run data (FR-01.47) — it is emphatically NOT the terminal: no xterm, no pty, no WebSocket, no input (guarded by test), and the real embedded terminal stays byte-identical in the Files & Terminal tab. Durations always render `n/a` (never synthesized), an empty log yields an honest empty summary (never invented lines), and untrusted event-log text is sanitised (control/bidi characters stripped, length-capped) before render. Every sentence comes from the Mission narrator (FR-01.54); a design gate routes to A14's surface with an honest placeholder until it lands. State is consumed from A11's `useMissionState` (no second derivation). Only the `/tasks/:taskId` Mission-tab (done + live) visual baselines move (FR-01.56).
- Mission Control "The Record" rail: one clickable spine that merges the process rail and the trace chain into a single artifact (absorbing the former TraceChain) — five state-derived nodes (Requirement · Spec · Tests · Review · Commit), each carrying its receipt, that open an artifact panel (an inline card on the photo, a scrimmed slide-over on narrow screens) whose "Open full document" routes to the existing Files & Terminal viewer. Node state and every receipt are derived honestly from real per-run data (FR-01.47) — a step with no evidence reads "pending" with no receipt, a held review never shows "clean", a run with no commit never invents one, and a design gate shows the Design step as current. Adds the three Grade / Tests / Serves instrument chips (live values with run data, an honest "—" without) and the shared `useMissionState` derivation the rest of Mission Control consumes. The task detail gains a Mission | Files & Terminal switch; the terminal stays the default view (FR-01.55).
- The Command Center now has a small, consistent motion system — the grade ring counts up, the mid-run proof lines and Ship's-Log entries slide in, and the artifact panel eases open — applied only where the movement means something (something arrived, is running, or a value is counting), never as decoration. Crucially, if your system is set to reduce motion (as Windows is when animations are turned off), every screen shows its complete, final state immediately: all content present and fully visible, counters showing their final number, the ring showing its full arc — nothing is ever hidden behind an animation. The embedded terminal is untouched.
- Groundwork for the new Mission Control view: a plain-language "narrator" turns each run's real facts (the requirement it serves, its test count, its review verdict) and the pipeline/iterate phase steps into the exact approved wording, with an honest "n/a" wherever a fact isn't available yet — it never invents a number, count or outcome it didn't read. Security is shown as a separate CI check, never as a pipeline phase. No visible change on its own; the screens that render these words arrive next.
- `npx @svenroth-ai/shipwright@latest` — one command to install **and** update the whole system (the `/shipwright-*` SDLC plugins **and** the Command Center), first run and every run after. A new `bootstrapper/` npm workspace ships the built server + client, so re-running the command is the update (no clone, no `make`, no `git pull`): it verifies prerequisites (claude, uv, a working Python — rejecting the Microsoft-Store `python3` alias stub — Node ≥ 20.12, git), installs/updates every plugin **read from the marketplace manifest** (never a hardcoded list — the README said "13" while the manifest lists 14) and syncs the plugin cache so each plugin's hooks actually resolve (`claude plugin install` alone never delivers the `shared/` tree, leaving every hook dead at session start), then boots the Command Center on `:3847` — or attaches to a running one, swapping an older one in place via a detached swapper so it is safe to run from inside the Command Center's own terminal, and leaving any foreign process on the port untouched. `/api/diagnostics` now additively reports the WebUI's own `app.name` + `app.version` (the attach-vs-swap signal). Publishing stays a manual maintainer step (FR-01.49).
- Per-run data join: read-only `GET /api/external/projects/:projectId/{runs,runs/:runId,grade-trend}` endpoints (plus `lib/runDataApi.ts` + `useRunData` hooks) that turn the tracked event log into the per-run shape the Mission-Control / Ship's-Log / board surfaces consume — a run joined to its affected FRs, test counts, DERIVED gate lamps (flagged as derived, never an authoritative verdict), iterate phase-timings, and a grade-trend series folded from `grade_snapshot` events. Honest degradation throughout: an unknown run or a run without timings returns `null` (rendered `n/a`) — durations are never fabricated (FR-01.47).
- The Projects page is now a gallery of Ship's-Log preview cards instead of a plain table. Each project is a card showing its colour, name, compliance grade, and — the point of the change — a preview of its logbook: projects that have actually been run show a small runs sparkline, a "N runs · M FRs · score/100" line, and a quote from the most recent run's summary; projects with no runs yet show an honest "No runs yet — grade it to open the logbook." sentence instead of a fake, empty chart. Every number is read from real run data — nothing is invented, and while the data is still loading (or if it can't be read) the card says so rather than falsely claiming "no runs". Projects that have a logbook sort to the front, so a board with many projects leads with the ones that have real history. The gear (settings) and trash (remove, with its task-cascade warning) work exactly as before. If a release published only *some* of a run's decisions — which can happen, because decisions are published one at a time — the ones already published and the ones still waiting are now **both** shown, each labelled correctly. Previously the moment any decision had been published, the rest stopped being looked for at all, and a decision still waiting simply disappeared with nothing to indicate it. Throughout, "we could not read the records" and "nothing was decided" are kept apart: an unreadable record says so plainly, a genuinely empty one stays quiet, and a single damaged record no longer hides the good ones alongside it — those still show, with a note saying how many could not be read. ### Security

- Pinned all first-party GitHub Actions in CI workflows to full commit SHAs and added a grouped weekly Dependabot config (github-actions) so they stay current — supply-chain hardening that clears the Semgrep mutable-action-tag and OpenSSF Scorecard pinned-dependencies findings.
- The accepted `github-actions-mutable-action-tag` risk is registered in `.trivyignore.yaml` with an expiry, so the compliance dashboard flags it for re-review instead of the decision rotting unnoticed. To be explicit: this records an accepted risk accompanying a deliberate *un*pinning of GitHub-owned actions — it is not a hardening. Third-party actions remain SHA-pinned, which is where tag-repointing is an actual threat.
- The vendored Tier-3 PR reviewer (`scripts/ci/`) now fails closed when it reviewed nothing at all — an empty fetch, a diff with no file headers, or a pull request whose every file was filtered as a regenerated artifact. Previously the model was handed an empty diff and answered "approve", turning a required check green over a change nobody read.
- A pull request can no longer hide a file from review by naming it after one the reviewer skips. Three places quietly trimmed spaces from file names, so a file called "<a-generated-file> " (with a trailing space) was dropped from the review AND reported under the innocent file's name. Names are now compared exactly as they arrive.
- Contributor-chosen file names shown to the review model are now inert: invisible and text-direction characters are stripped (including the Tags block used to smuggle hidden instructions), each name is length-bounded and quoted, and the prompt states before the list that these are untrusted data. The diff itself can no longer be pushed out of the untrusted region by a file named after a template placeholder.
- Bumped linkify-it to 5.0.2 (CVE-2026-59887, quadratic mailto: DoS) and dompurify to 3.4.12 (GHSA-c2j3-45gr-mqc4) via a targeted lockfile refresh — both patches sat inside the existing semver ranges.
- Accepted security risks are now enforced by CI, not just recorded. A new `Accepted-risk register (gate)` job fails the build when a suppression has no register entry, when a register entry has no suppression, or when an acceptance is past its re-review date. It runs on every PR **and** on the existing weekly schedule - the schedule is the load-bearing half, because expiry is time-based and a PR-only gate would never fire on an entry that lapses during a quiet week.
- Accepted-risk CI gate re-vendored from upstream: deleting `shipwright_accepted_risks.yaml` no longer exempts the drift check (it now reconciles against an empty record), and a `.trivyignore.yaml` entry whose own `expired_at` has passed is no longer counted as an active suppression — it surfaces as STALE with renew-both-dates advice instead of reporting the register reconciled.
- The vendored gate's provenance is now machine-checked: each module's header must agree with the manifest (repo, path, commit, hash, and the embedded `git show` reproduction command), and the drift + provenance guards run on the weekly scheduled security job rather than on pull requests only.
- PR review is now two-staged and fails closed: a pull request raised from a fork is reviewed instead of silently passing. The required `PR Review` check used to be a job, and GitHub scores a SKIPPED job as a successful required check - so the fork guard that kept credentials away from untrusted code also handed every fork PR a green status with nothing reviewed. The check is now a commit status posted by a second workflow that runs from the default branch; if it never reports, the context is absent and the merge blocks.
- The `skip-pr-review` label no longer waives review of a change to the checks themselves. The tier decision now runs from default-branch code over GitHub API data - not from the pull request's own copy of the workflow - and classifies CI workflows, git hooks, the vendored reviewer, and the security-suppression channels (`.trivyignore.yaml`, `shipwright_accepted_risks.yaml`, `.semgrepignore`, `.claude/settings.json`, the bloat baseline) as always-review.
- Windows command invocation no longer goes through the platform shell to find a `.cmd` shim. The Claude CLI version probe and the three `npx` installer helpers (CLI wrapper, prerequisite prober, browser opener) now resolve the real executable via PATHEXT and invoke a shim through an explicit `cmd.exe /d /s /c`, so an `.exe` target involves no shell at all. The four inline scanner suppressions are deleted rather than registered as accepted risks, and a CI-running source scan keeps them from coming back.
- The Semgrep scan-scope list (`.semgrepignore`) and every inline suppression directive are now pinned by CI: adding to either fails the build until the pinned set is updated with a written rationale, closing the two suppression channels the accepted-risk register gate structurally cannot see. Both jobs that enforce it are required checks, so it is merge-blocking rather than advisory.
- Narrowed the `server/scripts/` scan-scope exclusion to the three genuinely non-shipped files. `copy-assets.mjs` is wired into `npm run build` and decides what lands in `dist/`, so it was production code being excluded from the security scan; it is back in scope, and a new file added to that directory is scanned by default.

First: when another window or process is briefly holding the lock on the app's task file, several actions — closing, forking, creating, launching, or deleting a task, dismissing an inbox item, saving settings, or deleting a project — used to fail with a blunt 500 error, even though the same situation on the task-edit action already returned a friendly "locked, please retry" (409) response. All of these now return that same retryable "locked, retry" response, so the app can simply try again instead of showing a hard error. Second: sending an empty or malformed request body to the settings-save or project create/edit actions used to crash into a 500; it now returns a clear "invalid request body" (400) response. Nothing changes for normal, well-formed requests — the fix only replaces misleading 500s with the correct 409/400 the app already knew how to handle.
- The pipeline progress card no longer disappears from the Command Center board when a single background read of a project's run-config file is briefly interrupted mid-run (campaign webui-deep-audit D10, F15). On Windows the orchestrator rewrites shipwright_run_config.json on every phase transition, and one poll could catch that rename window: the server returned an "invalid" result and the board latched its 5-second polling OFF, so the Pipelines lane vanished and only came back after switching windows or navigating away. The read now retries the same brief filesystem hiccups on the existence check (not just the file read) and keeps a valid copy for 30 seconds so a torn read never surfaces as invalid, and the board keeps polling on a light 10-second backoff so any transient flap heals on its own. Genuinely-missing or malformed configs behave exactly as before.
- The daily/boot cleanup that deletes old terminal scrollback files no longer throws away a still-active task's saved history (campaign webui-deep-audit D16, F25). Each terminal task keeps its scrollback in two files: a live file and one rotated archive. The cleanup is meant to skip a task entirely if either file has been touched recently. Previously it decided file-by-file in the order the operating system happened to list them, and for the common alphabetical order it visited the fresh live file first, harmlessly, and then still deleted the older archive of that same task — so a task you had used recently could silently lose the earlier part of its terminal history. The cleanup now groups both files of a task together and skips the whole task whenever either file is recent, regardless of listing order, and still removes a fully-expired task in one step. Nothing visible changes for current tasks; the fix only prevents premature deletion of a live task's archived scrollback.
- Interrupted terminal-snapshot writes no longer leave secret-bearing staging files on disk forever (campaign webui-deep-audit D19, F26). When the app saves a terminal's on-screen state it first writes a temporary staging file and then renames it into place. If the app was shut down (or a Windows file lock persisted) at exactly the wrong moment, that staging file — which holds the full terminal screen, possibly including secrets — was orphaned, and nothing ever cleaned it up: the delete-a-task cleanup only removed the finished snapshot, and the periodic disk sweep only matched scrollback logs. Now a task deletion also reclaims that task's orphaned staging files, and a boot-time plus once-a-day sweep removes any staging file older than an hour (old enough to be provably abandoned, so a save that's still in progress is never touched). Live snapshots and scrollback logs are untouched. Nothing visible changes for current tasks; the fix only stops the slow leak of abandoned terminal-state files.
- A dev server you start inside the embedded terminal (for example npm run dev for another app) no longer accidentally inherits the Command Center's own network port settings and clashes with it (campaign webui-deep-audit D12, F17). On a deployed server the Command Center is launched with PORT set to 3847, and every embedded terminal used to inherit that value plus its sibling VITE_PORT / HONO_HOST settings - so a port-honouring dev server started in the terminal tried to bind the same 3847 and collided. The embedded terminal now starts with a clean network slate, so your dev server picks its own default port. This is a terminal-environment hardening fix only; nothing else in the Command Center changes.
- sdk-sessions.json persist() now re-reads and 3-way merges under the proper-lockfile critical section and writes atomically (tmp+rename), so two concurrent webui instances sharing ~/.shipwright-webui no longer erase each other's task rows or clobber externally-written daemon claim fields (FR-01.08 / FR-01.09).
- Creating or forking a task with an invalid title now fails cleanly instead of poisoning the task for every later launch (campaign webui-deep-audit D22, F27): POST `/tasks` and POST `/tasks/:id/fork` now validate a supplied title with the exact rule the rename (PATCH) endpoint already applies — embedded newlines (CR/LF/CRLF) and over-long titles are rejected up-front with a 400 and the same error message, so an automated writer (a run-config phase title, a triage "fix now" seed, or the leadwright daemon) can no longer persist a title that makes every subsequent Launch/Resume crash with a 500. A rejected fork no longer leaves an orphaned half-created child task behind, and an absent or blank title still falls back to the usual "Untitled task" / "<parent> — fork" default. The shared `normalizeTitle` helper makes create, fork, and rename share one validation contract.
- The Transcript view for a finished task no longer keeps re-reading the session file forever, and each open task page now makes a single transcript request per second instead of two (campaign webui-deep-audit D15, F21 + F22). Previously, opening a task that was already done (or had failed to launch) and leaving the tab open kept the app polling that task's transcript once a second indefinitely, even though it was meant to stop once the task reached a final state. Separately, every open task page ran that once-a-second read twice — the page body and the header each polled on their own — doubling the disk reads and network payloads per open tab. Now the poller stops as soon as the task is done or launch-failed, and the model name shown in the header comes from the single shared poller rather than a second one. Nothing visible changes: the transcript, the model label, and live updates all behave the same, just with less wasted work.
- Transcript-poll state machine no longer resurrects terminal-state tasks (campaign webui-deep-audit D06, F04/F23/F24): a `done`/`launch_failed` task stays put on every background poll — it never flips to `jsonl_missing` when Claude's 30-day cleanup deletes its JSONL, and a closed row with no recorded `firstJsonlObservedAt` is never yanked back to `active`. The ok-branch now dirty-checks the JSONL mtime so an idle/terminal task stops rewriting the whole `sdk-sessions.json` store every 1 s poll (patch + persist only fire when a value actually changed). `SessionWatcher.findByUuid`'s discovery `stat`/`readdir` now run inside the torn-read `readWithRetry` envelope (transient EBUSY/EPERM/EACCES retried; a genuinely-absent projects dir stays a fast miss via `ENOENT_FATAL`), so a momentary AV-scanner / OneDrive lock during discovery no longer produces an authoritative "JSONL missing" + state flip.
- Embedded terminal: preserve terminal scrollback across repeated detach/reopen cycles - the last-detach snapshot flush no longer overwrites a richer saved snapshot with a thinner one (e.g. after a Claude TUI screen clear)

### Security

- The Preview button's opened URL is now host-pinned to your local dev server (D21/F10): a hand-authored project profile whose `dev_server.ready_path` smuggled another host (e.g. `@evil.com/`) could previously redirect the opened preview off your machine — the returned URL is now built through the same localhost-pinning sanitizer the readiness probe uses, so a malicious or malformed path can only ever land on your own dev server (or its root), never off-host.

- Auto-launch from TaskCard / NewIssueModal now reaches the embedded terminal deterministically (post-finalization UAT-fold). Previously failed in roughly half of clicks: when a new WebSocket attached to an existing pty (StrictMode dev double-mount; or a genuine multi-tab handoff), the server emitted `ready{role:"reader"}` followed within ~5 ms by `writer-promoted` once the previous writer's close handler fired, but the client cancelled the pending launch immediately on the first reader signal — losing the launch before the promotion landed. `TaskDetailPage.handleTerminalReady` now defers the reader-cancel by a 1500 ms stability window; the cancel is cleared when the role flips to writer (the typical promotion case) and only fires when the role genuinely stays reader (real second-tab scenario). (e) `EmbeddedTerminal` refs reset on `taskId` change so the prior task's "data seen" / "consumed token" state can't short-circuit the next task's prompt-readiness handshake. New `client/e2e/flows/75-launch-matrix-and-session-persistence.spec.ts` adds API-level launch-matrix coverage (4 direct-launch tests assert correct slash command per action-id, 4 backlog-launch tests assert `task.actionId` is recovered server-side, 1 session-persistence test verifies pty identity across WS detach/re-attach).
- Plain Claude (new-plain) tasks no longer show a phase pill on TaskCard, TaskList, or TaskDetailHeader.
