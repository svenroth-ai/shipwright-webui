PR review is now two-staged and fails closed: a pull request raised from a fork is reviewed instead of silently passing. The required `PR Review` check used to be a job, and GitHub scores a SKIPPED job as a successful required check - so the fork guard that kept credentials away from untrusted code also handed every fork PR a green status with nothing reviewed. The check is now a commit status posted by a second workflow that runs from the default branch; if it never reports, the context is absent and the merge blocks.
