6. Error states

Rule: when something is wrong, never show "nothing due". Say what is wrong.

a) The reminder tool is not available

CLI call: uv run ... reminder_cli.py due --json -> could not start / non-zero exit / unreadable answer / unknown contractVersion
Reminders are unavailable. The Shipwright reminder tool could not be started (or answered in a format this WebUI does not know). The reminder features are switched off until this is fixed.

The alert badge is replaced by a grey "?" so it is not mistaken for "all clear".

b) Triage could not be read (triageError set)

CLI call: reminder_cli.py due --json (field triageError)
Parked triage items could not be checked, so this list may be incomplete. Reminders are shown below. (Detail from the tool: "triage.jsonl: unreadable at line 12")

c) Damaged line in the reminder file (reminderCorruptLines > 0)

CLI call: reminder_cli.py due --json (field reminderCorruptLines)
2 lines in the reminder file are damaged and were skipped; the reminders on them are not shown. Ask Shipwright to repair the file (the WebUI never edits it). Shown only when the count is above 0.

d) Mail could not be sent

CLI call: none (server-side SMTP send)
Mail to operator@example.org failed: connection refused by smtp.example.org:587. The item stays in the alert. The server tries again at the next check (at most 3 tries per item and day). Open mail settings
