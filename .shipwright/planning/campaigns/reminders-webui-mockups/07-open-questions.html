Open questions for you (plain language, each with a recommendation)

  1. Where should the alert appear? Small badge in the header, a banner on the board, entries in the Inbox, or a mix. Recommendation: badge + Inbox entries; banner only for items overdue by more than a day.
  2. Do you want mail at all? If not, the mail and timer part (W3) is dropped and the work shrinks. Recommendation: yes, but mail off by default so nothing is sent before you set it up.
  3. One mail per item, or one daily summary? The plan says one mail per item and day; with many due items that can be many mails. Recommendation: one mail per item, but if more than 5 are due at once, send one summary instead.
  4. Parked triage items that expire stay due every day until you act. Should they also mail you every day? Recommendation: mail once when the park expires, once more after 7 days, not daily; the alert still shows them every day.
  5. Can you create reminders in the WebUI form? It only runs when you press Create. Recommendation: yes, form on the due-list page.
  6. Which projects are checked? Only the selected project, or all projects? Recommendation: all registered projects for alert and mail, with the project name on every item.
  7. How often should the server check? Recommendation: every hour, plus once at server start. The server must be running; no reminder arrives when it is off (already accepted).
  8. Where is the mail password kept? Recommendation: in the WebUI's own data folder outside any repository, never shown again after saving.
  9. Snooze: free date or presets? Recommendation: date picker with quick buttons (tomorrow, next week).
  10. Done for a parked triage item? Reminders have Done/Snooze; triage items are acted on in triage. Recommendation: keep it that way; the list only links to the triage item.
