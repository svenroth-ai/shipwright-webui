# Iterate Spec: org-page

- **Run ID:** iterate-2026-08-26-org-page
- **Type:** feature
- **Complexity:** medium (overridden from classifier's `small`/0.6-confidence result — positive evidence: a brand-new page with zero precedent UI components (badge/switch/stat-row all new), a new server-side architecture pattern bridging the host+secret-gated `/api/external/org/*` family into the plain `/api/*` surface, a new client/server type-mirror pair needing a drift guard (CLAUDE.md rule 7), a two-site conditional-nav change (sidebar + command palette), an 8-endpoint data integration, and an explicit operator request for a mid-build visual approval checkpoint)

## Goal
Give the operator a Command Center page — "Org" — that shows their AI leads
(from the separate `leadwright` tool) the same way the approved mockup shows
them: an org chart at the top, shared organization documents, then one card
per lead with five blocks in a fixed order (identity, role, current activity,
capacity stats, documents). The block order is a promise: a later per-lead
detail page is this same card enlarged, so the sequence must not change later.

  that is a server contract change with its own review surface and existing
  contract tests; if the page cannot ship without it, stop and escalate
  rather than widen it here. Consequence, stated plainly: `parallel` and
  `projects` render "not measured" permanently in this iterate (see Stats
  source table in Design Notes) — this is a known, accepted gap, not an
  oversight to fix later in this same run.
- A working pause/unpause action — no route exists; the switch stays
  disabled.
- Editing `org-chart.json` or `conventions.md` (the mockup's other two
  "Bearbeiten" shared-doc tiles) and the "+ add lead" ghost card — the
  shared-documents block is GET/view-only this iterate; only a lead's own
  `charter.md` is writable (see AC-10 and the write-surface note below). The
  ghost card renders but is disabled/non-interactive, same treatment as the
  pause switch.
- A per-lead detail page (the promised "this card enlarged" follow-up) —
  explicitly future work.
- The `lead_question` / Inbox "waiting on you" surface (leadwright
  FR-04.15–FR-04.19) — that capability is being built separately in the
  existing Inbox, not here; see the Now-block Design Note.
- `decisions-proposed.md` / countersign / cron / decisions-lock machinery
  as a **write target** — `withDecisionsLock` is reused only insofar as the
  underlying, unmodified `external/org/*` write path already uses it for
  `decision_log`/`decisions_proposed` kinds; this iterate's new browser
  write surface never targets those kinds at all (403, see AC-10).
- Any new authentication mechanism for the browser — the new proxy route
  drops the `x-shipwright-leads-secret` gate only (the browser is a
  first-party caller); the host allowlist (`isAllowedOrgRouteHost`, a
  PO-decided control, FR-04.38) is retained on the new surface unchanged —
  see Design Notes. This is a deliberate, narrower relaxation than "no
  auth", not an absence of one.

## Design Notes

> **Revised after Internal Plan Review (opus-plan-reviewer) + External LLM
> Review (Branch A, both deepseek and openai verdict `revise`).** The
> original version of this section had a false central premise — see the
> first sub-note below — plus several under-specified surfaces the reviews
> caught with source citations. All findings are fixed here (none declined
> or disclosed); nothing was HIGH-severity-and-unresolved going into build.
> Full findings: iterate ADR (once written) + review-record `plan_internal`
> and `plan` rows.

**Server-side proxy route — extract pure cores, don't re-implement (fixes
Internal Review finding: false "no re-implementation" premise, HIGH).** The
exported symbols in `server/src/external/org/*.ts` (`parseOrgChart`,
`cronIntervalMs`, `evaluateStaleness`, `evaluateRegisterHealth`,
`readRegisterFileTolerant`) are **leaf math only**. The containment/
symlink-guard/error-discrimination logic — the lstat symlink check,
`realPathGuard` containment, ENOENT→missing vs 404-vs-500 discrimination,
the `measured:false` vs `measured:true,staleness:'unknown'` tri-state —
lives **inside each route handler's closure**, unexported. A prior external
review already found a HIGH (symlinked `org-chart.json` served arbitrary
file contents) and a MEDIUM (array-valued `leads` silently accepted) bug
exactly in that closure layer, fixed in-place. Calling only the exported
leaf math from a new route would silently drop those fixes' surrounding
guards. **Fix:** extract each handler body into an exported pure core
returning `{status, body}` — the shape `file-write.ts`'s private
`performWrite` already uses — for `org-chart.ts`, `usage.ts`, `last-run.ts`,
`beat-register.ts`, `file-read.ts`. Both the existing `registerXRoute`
(mounted unchanged, on its existing gated path) and the new `/api/org/*`
proxy call the **same** exported core. Existing `__tests__/routes.test.ts`
must stay green, unmodified, proving the extraction changed no observable
behavior on the gated family.

**Two gates on the existing family, only one dropped (fixes Internal Review
finding: silently-dropped host allowlist, HIGH).** `createOrgRouter` applies
`isAllowedOrgRouteHost` (loopback ∪ Tailscale `100.64.0.0/10`, explicitly
403s a bare `0.0.0.0`/`::` bind) **before** the secret check — a PO-decided
control (FR-04.38 Auflage 1, 2026-08-16) independent of the secret. The
plain `/api/*` surface has only a CORS-origin check, which is not a bind-host
control. **Fix:** the new `/api/org/*` router mounts `isAllowedOrgRouteHost`
as its own middleware — same allowlist, unchanged. Only the secret check is
dropped (the browser is a first-party caller of its own server). Under
`SHIPWRIGHT_NETWORK_PROFILE=open`, the org data stays exactly as reachable
as it is today — no wider.

**No route-mount collision (fixes Internal Review finding, MEDIUM).**
`server/src/routes/org.ts` declares its **own** absolute paths under
`/api/org/*` and never calls a `registerXRoute` from `external/org/*` — it
only imports the newly-extracted pure cores. AC-9 is the regression guard:
the existing secret-gated family must still 401/403 without the header
after the new router mounts, proving no double-registration shadowed it.

**Write surface narrowed to `charter.md` only (fixes Internal Review
finding: unlocked write reaches `decision_log.md`, HIGH).** `file-write.ts`
routes `decision_log`/`decisions_proposed` kinds through `withDecisionsLock`
because leadwright's own daemon is a second writer of those files — a
generic `path=` proxy on the plain surface would let the (now-absent) secret
alone have gated a write that bypasses that lock. **Fix:** the new PUT proxy
accepts and forwards **only** `kind: charter` for the calling lead's own
`charter_path`; every other allowlisted kind (including `decision_log`,
`decisions_proposed`, `conventions`, `principal`) is refused 403 (AC-10).
The shared-documents block and the other two "Bearbeiten"-labeled mockup
tiles (`org-chart.json`, `conventions.md`) are out of scope this iterate
(see Out of Scope) — GET-only.

**One composite endpoint, not N+1 (fixes Internal Review finding, MEDIUM).**
`readLeadOrgInfo` re-parses the whole `org-chart.json` per call; a
role+status+usage-per-lead fan-out would mean ~3×leads synchronous,
event-loop-blocking reads per page load. **Fix:** `GET /api/org/leads`
returns the whole roster (per-lead role sentence, Now-state, usage) in one
response, parsing `org-chart.json` **at most twice per request, never
per-lead** — once via `orgChartCore` for the roster body, once via
`readAllLeadOrgInfo` for the cron/reports_to lookup shared across every
lead (the two stay separate parses because `orgChartCore` full-validates
every lead all-or-nothing, while the lookup must tolerate one broken lead
elsewhere in the file — see `org-chart-lookup.ts`'s header). A per-lead
endpoint is added only if a later per-lead detail page proves it needs to
refetch in isolation — not built this iterate. React Query
`staleTime`/`refetchInterval` is wired to the existing
`LEADS_USAGE_REFRESH_INTERVAL_MS` (`_helpers.ts:197`, 5 min), never a
newly-invented interval.

**Type mirror — canonical shapes live in `server/src/types/org.ts`; the
guard compares union arms (fixes Internal Review finding: the planned
re-export + textual-interface guard cannot parse a discriminated union,
HIGH).** `UsageResponse`, `LastRunResponse`, `BeatRegisterHealthResponse`
are `type X = A | B` unions — a re-export has no `interface` body for a
textual guard to find, and even adapted, a flat field-name set can't tell
which union arm a field belongs to. **Fix:** declare
`OrgChartView`/`OrgChartLeadView`/`UsageResponse`/`LastRunResponse`/
`BeatRegisterHealthResponse`/`BeatRegisterEntryView` **verbatim** in
`server/src/types/org.ts` (canonical, matching `types/triage.ts`'s
direction — not a re-export), and have `external/org/*.ts` **import** from
there instead of declaring inline. `client/src/lib/orgApi.ts` mirrors the
same shapes. `org-schema-sync.test.ts` is purpose-built, not a copy of
`triage-schema-sync.test.ts`: for plain interfaces it uses the existing
textual-brace-body approach; for each union type it splits the type body on
top-level ` | ` arm boundaries, keys each arm by its literal discriminant
(`measured: false` / `measured: true` / `status: "clear"` etc.), and
compares per-arm field sets against the client mirror. Falsified locally
before being declared done (drop a field from the client mirror, confirm
red, then restore) — not committed as a scratch state, just verified.

**NOW block — "waiting on you" is unreachable, by design, not by oversight.**
The mockup's illustrative "wartet auf dich" example has no backing route:
`beat-register` reports `clear | open | fault(duplicate-session-id)` and
`last-run` reports staleness — neither says a lead is blocked waiting on the
operator specifically. Modeling: `beat-register.status === "open"` → **Running**
(a beat is genuinely open right now); `status === "fault"` → a fourth,
honestly-labeled alert state ("Needs attention — duplicate session"), never
silently folded into Resting; `status === "clear"` → **Resting**, with text
sourced from `last-run` (`measured:false` → "No runs recorded yet",
`measured:true` → "Last active {relative time}"). **"Waiting on you" (the
`.wait` orange state) is never rendered** — there is no data to justify it,
and per `leadwright/spec/lead-model-spec.md` (§4.4, FR-04.19) this is by
architectural decision, not a gap: a lead's question-to-PO state is already
owned end-to-end by the Inbox's `lead_question` kind (a 4th inbox-aggregator
type, going through the existing bell/"waiting on me" UI), and the leadwright
spec explicitly names a second "waiting" concept elsewhere as the mistake to
avoid. Confirmed with the operator before build — approved.

**Markdown modal reuse — additive, not breaking (fixes both external
reviews' finding: widening risks the existing caller, MEDIUM).**
`MarkdownEditorModal.tsx`'s load/diff/conflict/save state machine is kept
as-is; it currently hardcodes `projectId`+`path` against
`markdownFileApi.ts` (which calls `/api/external/file`, a project-scoped
route). **Fix:** the injected `{ load, save }` pair is an **optional** prop
pair defaulting to the existing `projectId`+`path` behavior when omitted —
the existing project-file caller passes no new props and its tests (save,
stale-ETag 409 conflict, reopening a different document after an error)
stay green unmodified. This iterate adds a sibling `orgMarkdownFileApi.ts`
(mirrors `markdownFileApi.ts`'s exact shape: `loadMarkdownForEdit`/
`saveMarkdown`/`MarkdownConflictError`) pointed at the new org proxy route
and passes it as the new optional pair for the Org page's caller only.

**Stats block — a figure-by-figure source table (fixes Internal Review
finding: two of five figures have no data source, HIGH).**

| Figure | Source | Measured when | Renders |
|---|---|---|---|
| Cadence | `readLeadOrgInfo().cron`, formatted | cron resolvable | formatted cadence text |
| Parallel | *(none — `max_concurrent_tasks` deliberately not projected by `org-chart.ts`, see its file header)* | never, this iterate | "not measured" |
| Budget | `usage.ts` `costUsd` + `windowDays` | `measured: true` | "`{windowDays}`-day budget", currency figure |
| Projects | *(none — `manages` is Lead-of-Leads hierarchy per `leadwright/lib/org-chart.ts:7-9`, not a project list; no route projects a lead's project set)* | never, this iterate | "not measured" |
| Runs | `usage.ts` `runCount` (same payload as Budget) | `measured: true` | run count |

`parallel`/`projects` are a stated, accepted gap (see Out of Scope) — never
a zero, never inferred from `manages.length`.

**Docs block — view-only contract for non-charter documents (fixes External
Review finding, MEDIUM).** `learnings.md` renders through a **read-only**
markdown viewer (the same rendering pipeline `MarkdownEditorModal` uses for
its content, with no edit affordance, no save path, no `{load,save}` pair
needed — just fetched text run through the existing markdown renderer).
`audit.jsonl` is **not** markdown: render as a bounded, latest-N-entries
structured log view (never an unbounded raw-text dump), with a way to see
older entries rather than fetching the whole growing file at once. Each
doc tile (shared or per-lead) shows a visible "not found" state for a
missing file rather than a blank or broken tile.

**Role extraction — precise rule (fixes External Review finding, LOW).**
Parse `charter.md` with the project's existing markdown pipeline; skip YAML
front matter and heading lines; select the first paragraph of plain prose
(skipping code fences and blockquote-only content); strip markdown
link/image syntax from the extracted text; take the first sentence up to a
bounded character cap. Return `{ measured: false }` — never a dumped first
paragraph — if no usable prose sentence exists.

**Nav presence — an explicit 4-state hook, filtered at each read site
(fixes both external reviews' finding: naive success/fail hides the
502/broken case, MEDIUM; and Internal Review's finding that
`navDestinations.ts` cannot itself be async, MEDIUM).** `getNavDestinations()`
(`navDestinations.ts`) is a **pure, synchronous** function over the static
router table — per its own stated invariant (A21/FR-01.65), a hand-typed
conditional inside it would be a second source of truth for palette
membership, and it stays untouched. **Fix:** a single
`useOrgChartPresence()` hook returns `"loading" | "present" | "absent" |
"broken"` (never a bare boolean). `absent` fires **only** on a confirmed
`org_chart_missing` 404 — never on network error, while loading, or on 502.
`SidebarNav` and `CommandCenter.tsx`'s consumption of
`getNavDestinations()`'s output **both** filter on this one hook (component
test asserts both call sites read the same signal — the "two places, one
condition" trap the source card names explicitly). Direct `/org` navigation:
`loading` → page-level loading state; `present` → render; `broken` → render
with the page-level error naming the failure (AC-7); `absent` → the
"not installed" empty state (AC-6b). This is the first conditional entry in
either registry — recorded as a named exception to A21 in
`architecture.md`, not left as an undocumented deviation.

**No precedent components.** Badge, disabled-switch, and stat-row are new,
hand-built primitives (confirmed zero existing matches in
`client/src/components/common/`) styled from the mockup's own CSS shapes.

## External-Code-Review Findings

Branch A (openrouter; `openai` succeeded, `deepseek` returned an empty reply
— `degraded: false` overall since one leg succeeded, `contradiction.detected:
false` with `requires_resolution: true` noted, since only one reviewer
answered). `openai` verdict: `revise`. Findings addressed before commit —
all seven, `accepted-and-fixed`:

1. **HIGH, security — unauthenticated leadId on the charter write.** The PUT
   proxy validated `leadId`'s shape (`LEAD_ID_RE`) and that the resolved
   target was kind `charter`, but never confirmed `leadId` is an actual
   `org-chart.json` entry — any syntactically valid, unregistered lead id
   could get a `charter.md` written under `leadsRoot`. **Fixed:**
   `routes/org.ts`'s PUT handler now parses the chart (`orgChartCore`) and
   403s `unknown_lead` when `leadId` isn't `Object.hasOwn(chart.leads,
   leadId)`. Tests: `org.test.ts` "refuses a write for a valid-shaped but
   unregistered leadId" + "forwards the org-chart's own error when the
   chart is missing/invalid".
2. **MEDIUM, spec — composite read re-parses the chart per lead.** The
   Design Notes explicitly commit to "`GET /api/org/leads` parses the chart
   once"; `buildCadence`/`buildNow` (via `lastRunCore`) each independently
   called `readLeadOrgInfo`, re-opening and re-parsing `org-chart.json` once
   per lead. **Fixed:** `org-chart-lookup.ts` split into `readOrgChartRaw`
   (one open+parse) + `lookupLeadOrgInfo` (pure, in-memory) and a new
   `readAllLeadOrgInfo(leadsRoot)` that parses once and returns a per-lead
   lookup closure; `lastRunCore` gained an optional pre-fetched `orgInfo`
   dependency so the composite path never re-reads. The single-lead

## Stage-3 Doubt-Review Findings

Fresh-context adversarial pass (`shipwright-build:doubt-reviewer`), biased to
disprove — run because this iterate touches authorization logic (the
charter-write allowlist) and concurrent client state (AuditLogModal
pagination), both DO-listed triggers for Stage 3. Two findings, both fixed:

1. **HIGH, security — `requireChartLead`'s shape-check deferral let a
   URL-encoded trailing slash bypass chart-membership entirely on the PUT
   charter route.** Hono's route-param decode (`tryDecodeURIComponent`)
   turns `%2f` into a literal `/`, but its path-segmentation decode
   (`decodeURI`) does not — so a raw `leadId` of `"ghost-lead/"` (from URL
   segment `ghost-lead%2f`) fails `LEAD_ID_RE` (correctly, it has a trailing
   slash) while `resolveOrgAllowlistedTarget`'s own path-normalized
   derivation of "leadId" collapses that same string down to a clean,
   chart-registered target. `requireChartLead` was *deferring* on the
   `LEAD_ID_RE` failure (assuming the downstream core would re-validate the
   same raw string, true for the two GET routes but not for the PUT route's
   `resolveOrgAllowlistedTarget`), which let the write proceed with no
   chart-membership check at all. **Fixed:** `requireChartLead` now rejects
   (400 `invalid_lead_id`) directly on a raw-string shape failure, for all
   three call sites uniformly — `LEAD_ID_RE` matches only `[a-z0-9][a-z0-9-]*`
   (no `/` or `.`), so a raw string that passes it can never diverge from its
   own path-normalized form, closing the whole class rather than the one
   PoC. **Verified non-vacuous:** temporarily reverted the fix, confirmed
   the new regression test (`org.test.ts`, the `%2f`-suffixed-leadId case)
   failed with a 409 instead of the expected 400; restored the fix, test
   passed. `server/src/routes/org.ts:137`.
2. **MEDIUM, correctness — AuditLogModal's per-cursor-page `useQueries`
   rewrite (Stage-2 fix #3 above) had its own concurrency gaps.** A rapid
   double-click on "Load older entries" fired both handlers before either
   state update was reflected in a re-render, so both read the same stale
   `next` cursor from the same closure and both appended it (a duplicate
   fetch). Separately, reading only `queries[0]`'s `error` hid a failure on
   any later page — no error UI, no per-page retry — and the old
   `loadOlder()` re-derived the next cursor from `lastQuery.data?.nextCursor`
   (`undefined` on a failed page), silently re-fetching page one into a new
   slot instead of retrying the page that actually failed. **Fixed:**
   idempotent cursor push via the functional updater
   (`prev[prev.length-1] === next ? prev : [...prev, next]`); `error`
   derived from `queries.find(q => q.error)?.error`; `loadOlder()` calls
   `.refetch()` on the failed last page instead of re-deriving a cursor.
   Two new regression tests in `AuditLogModal.test.tsx`'s "doubt-review
   fixes" block (double-click dedup, per-page-error-then-Retry).
   `client/src/components/org/AuditLogModal.tsx:62`.

## E2E-Discovered Fix (Step 11a)

Authoring `org-page.spec.ts`'s invalid-chart (AC-7) scenario surfaced a bug
no unit test could see: on a real 502 (malformed `org-chart.json`), the
"broken" test hung indefinitely, and network instrumentation showed 500+
requests/sec against `GET /api/org/org-chart` that never stopped within the
test timeout. Root cause: three components share the one `useOrgChart`
query key (`SidebarNav`, `CommandCenter`, `OrgPage`), all mounted on every
`/org` load; TanStack Query's `retryOnMount` default (`true`) means each of
those three observers, mounting against an already-errored query,
independently triggers its own fresh outer fetch attempt — `retry: false`
only governs the *inner* retry decision within one fetch, not whether a
newly-mounted observer re-triggers the fetch at all. **Fixed:**
`retryOnMount: false` added to `useOrgChart.ts`; `staleTime: 60_000`
(already present) still lets a later genuine revisit refetch once that
window passes. Confirmed via the same E2E test: request count dropped from
1000+/sec (never settling) to a single fetch, all 4 `org-page.spec.ts`
tests pass. Full client suite (368 files / 3469 tests) and server suite
(319 files / 3698 tests + 3 skipped) re-verified green after this fix.
