# iterate-2026-09-16-mission-feed-render-fidelity

Bug-report-driven change to the Mission tab's activity feed (`client/src/components/external/mission/`, `client/src/lib/missionActivityFeed*.ts`). No formal interview/mini-plan phase — the user (Sven) supplied five concrete, screenshot-illustrated UX complaints directly; two judgment calls were resolved via `AskUserQuestion` before implementation began. This file stands in as the spec `spec-reviewer` checks the diff against.

## Requirements (user-reported, verbatim intent)

1. **Remove the header strip** above the activity feed (the small dark box showing `‹run-id› · n/a` / `✓ suite green — N passed`). Decided: remove it **always**, unconditionally — not just conditionally hidden for red states. Principle: the feed should read like Claude Desktop / Codex Desktop's own output, not an app-invented status strip.
2. **Tool-call commands must be collapsed by default.** A card's command chip(s) render as a single collapsed summary line ("N commands"); clicking it expands the chip row. Applies uniformly regardless of how many tool calls a card carries.
3. **Markdown must actually render**, not show as raw source. Applies to a turn's own prose wherever it can legitimately contain block markdown (headings, tables, bold) — `card.text` and `card.explanation` alike — through the existing sanitized `react-markdown`/`remark-gfm`/`rehype-highlight` pipeline (`MarkdownChunk`), never a raw `<p>` or `dangerouslySetInnerHTML` (CLAUDE.md DO-NOT #4). Does NOT extend to a card's own SYNTHESIZED sentence embedding raw, verbatim excerpted tool output (currently: a blocker's derived "A command failed: …" headline, item 4 below) — that string is never a turn's own authored prose, and markdown-significant characters inside the raw excerpt (`*`, `_`, `` ` ``, `[`) would otherwise be reinterpreted as formatting and garble the plain-language explanation. Rendered as a literal text node instead, gated on the explicit `ActivityCard.textLiteral` flag (18th/22nd-round external review catches, glm/openai — the latter initially misread this bullet as requiring the literal path too, before the scope note above was added).
4. **The Blocker card must explain what happened in plain language**, not just show a raw Python traceback + exit code + failing bash command with nothing a non-technical user can act on. Decided: keep the card, but show a plain one-sentence explanation derived from the command's own output up front, with the raw traceback/command collapsed behind a "Show details" disclosure (closed by default).
5. **A test run that is part of TDD authoring** (the freshly-written test file's own first run, immediately after being written) must not be given the same "Passing"/"Failing" gate-stamp treatment as a genuine whole-suite verification run — that misleads the user into thinking official verification occurred when it did not.

## Out of scope

- No changes to the underlying transcript parsing, MissionContext schema, or server-side artifact resolution.
- No new persisted/serialized format — `ActivityCard.authoringRun` is in-memory reducer output only.
- `OperationCard`/`ProofSummary`/`VerdictBanner` components themselves are unchanged; only their mount point for a COMPLETED run was removed (item 1) — the `mission-completed-stack` div that used to show both `OperationCard` and the feed together. The `designgate` mount point (`isDesignGate ? <OperationCard .../> : ...` in `MissionBody.tsx`) is untouched and out of scope: it predates this iterate and is a decision surface, not the run-id/"suite green" strip item 1 targets (18th-round external review catch, glm, low — this note previously said "live/designgate feed view", which overstated the change; `live` never had the mount point either).
